\section{Functional Requirements}
This requriments specify what application does. There are 12 functional requirements divided in 7 domains.
To define the functional scope for this section, an analysis of Netflix's business model and official domain vision was conducted to establish a comprehensive understanding of the operational context. Building upon this business domain baseline, an actor-driven requirement elicitation process was executed. System actors, ranging from end-customers to operational staff and data analysts, were identified and evaluated based on their operational responsibilities and system interactions. Each actor's functional needs, such as secure authentication, uninterrupted media streaming, content curation, and platform analytics, were systematically mapped to define the required system capabilities.

Subsequently, Domain-Driven Design (DDD) strategic design principles were applied to analyze and categorize the elicited requirements. The requirements were grouped into distinct Bounded Contexts, acknowledging that domain entities and ubiquitous language terms carry specialized business semantics and rules depending on their contextual boundary. Through this domain decomposition, the following core Bounded Contexts were identified:

\begin{itemize}
    \item \textbf{Identity and Access Management (IAM):} Manages user accounts, authentication credentials, and access control policies across the platform.

    \item \textbf{Subscription Management:} Governs membership plans, billing processing, and subscription lifecycle states.

    \item \textbf{Streaming Core:} Serves as the primary domain service responsible for video playback orchestration and real-time media streaming delivery.

    \item \textbf{Recommendation Engine:} Leverages user consumption history, search queries, and contextual metadata to generate personalized content suggestions.

    \item \textbf{Content Management:} Facilitates the complete lifecycle management (CRUD operations) for media assets and metadata across staging and release workflows.

    \item \textbf{Data \& Insights:} Captures, aggregates, and processes platform-wide performance and streaming metrics for analytical insights.

    \item \textbf{Catalog \& Discovery:} Handles content indexing, search queries, and catalog exploration to enable seamless user discovery.
\end{itemize}

\section{Non-Functional Requirements}
The non-functional requirements (NFRs) defined for the system are based primarily on publicly available information regarding the Netflix platform and its operational characteristics. The purpose of these requirements is to establish a realistic reference workload and performance context for the cloud-native prototype developed in this project. Some of the values presented correspond to reported Netflix figures, while others are estimates derived from those publicly available values using explicit calculations and assumptions. 

In cases where an official value was not directly available, an estimate was derived from the available information rather than introducing an arbitrary value. This approach allows the prototype to preserve a relationship with the real operational scale of Netflix while maintaining transparency regarding which values are directly documented and which are calculated approximations. 

It is important to emphasize that the functional prototype developed for this project will not reproduce the full production scale of Netflix.  

If the prototype remains stable under the simulated workload and demonstrates the expected behavior in terms of concurrency, request processing, availability, data management, and scalability, the architecture can subsequently be scaled horizontally by increasing the computational and infrastructure resources provided by the cloud platform. 

The objective is not to claim that the prototype can directly sustain Netflix-scale traffic with academic-level infrastructure, but to demonstrate that the system can maintain stability under representative workloads and that its architecture provides a practical foundation for increasing capacity through horizontal scaling as additional cloud resources become available.
